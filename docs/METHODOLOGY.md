# Methodology

This is the end-to-end method behind DoomForge: how data is generated, how the
agent is trained, how the diagnostic suite is built, and how decisions are
measured. Architecture details are in [`ARCHITECTURE.md`](ARCHITECTURE.md);
per-checkpoint numbers are in [`RESULTS.md`](RESULTS.md); the suite mechanics are
in [`../training/suite/README.md`](../training/suite/README.md).

---

## 1. Scope and constraints

- **Track 1, “Can It Play DOOM?”** The scorer imports `submission/agent.py`,
  constructs `DoomAgent(obs_space, act_space, device)`, calls `reset()` and then
  `act(observation)` on hidden maps.
- **No engine access at inference.** The agent sees only the observation dict.
  The teacher, A*, BFS, door state machines and map data are training-only.
- **Budget**: one CPU thread, 8 GB RAM, 2 GB VRAM, 60 s init, 10 s reset, 40 ms
  average decision, 5 s worst case. The shipped agent is CPU-only and measured
  at p50 1.7 ms / p99 2.1 ms.
- **Hidden scorer.** We optimize a diagnostic proxy suite and report every
  component; no claimed leaderboard score.

## 2. Problem formulation

A partially observable Markov decision process. Each decision advances four
engine tics. The action is a 9-bit vector generated by six factorised heads
(move 3, strafe 3, turn 3, attack 2, use 2, next 2), so the 216 legal joint
actions exclude contradictory button combinations.

The training reward mirrors the stated score components: exit +10, key +3,
locked door +3, ordinary door +0.5, new sector up to +10, new cell +0.01, kill
+0.6, damage −0.01/HP, early death penalty. The diagnostic proxy uses the same
assumptions and reports them separately, because the official weights are hidden.

## 3. Observations and agent inputs

| Input | Shape | Role |
|---|---|---|
| rays | 64 × {distance, hit type} | geometry, doors, enemies, items |
| visible entities | ≤32 × {distance, sin, cos, rel. velocity, type} | permutation-invariant threat/item list |
| vitals | 17 | health, armour, ammo, six key flags, velocity |
| RGB | 120×160×3 → pooled 30×40 | exit signs, door/key colour |
| previous action | 12 + turn-held | action history and turn dynamics |
| map crop | 6×32×32 | deterministic allocentric memory |
| pose | 6 | heading, velocity, position proxy |
| goal | 8 + type | learned objective (Atlas-G) |

The **map memory** is deterministic perception, not planning: heading comes from
the measured turn table, translation from ego velocity, and rays/items are
projected into a 64×64 grid at 64 units/cell. The crop adds a **frontier**
channel (visited free cells adjacent to unknown cells) on top of
visited/wall/door/locked/item. A learned readout consumes the crop.

The **goal head** is trained to imitate the privileged teacher's current
objective as an ego-relative 8-vector (dx, dy, distance, sin/cos bearing, type,
mask). At inference the goal is predicted from observations only and fused back
into the policy.

## 4. Map generation and splits

The generator emits node-less Doom binary maps (ZDoom builds BSP at load time),
with four layout families:

- tier 1 arena (cover, 4–8 monsters),
- tier 2 rooms (7–8 rooms, unlocked doors, loops),
- tier 3 progression (one key → one locked door → exit),
- tier 4 gauntlet (two keys, two locks, loops, scarce resources).

Rooms are carved by recursive splitting, doors are placed on every split wall,
and the exit is a walk-over line with a visible sign wall behind it. Locks get
coloured textures and matching key things. Every map records a `spec_hash` and
`generator_version` in the manifest.

Splits: train seeds 0+, val 10 000+, test 30 000+, OOD 40 000+. Freedoom maps
are split by file: train MAP01–16, val MAP17–22, test MAP23–32. Leakage is
checked by hashing every WAD; train/test hash intersection must be zero.

**A benchmark bug found and fixed.** The room generator's locked doors are
usually optional: only 5/30 tier-4 maps actually required a key, and 0/30
required two. A “key” category built on them measured nothing. C5, C6 and C8 are
therefore purpose-built drill layouts with cut-edge locks: key alcove → locked
door → exit (C5), red key → red door → blue key → blue door (C6), and a key
alcove behind the spawn with a lock ahead (C8). The privileged teacher solves
them 3/3, 5/5 and 3/3. This is documented as a benchmark-validity failure, not
hidden.

## 5. Privileged teacher and labels

The teacher is a training-only expert with map access:

- a 16-unit navigation grid built from linedefs, with door cells, lock colours,
  exit goals and agent-radius wall inflation;
- A* with door costs, key gating and frontier fallback;
- a door state machine (approach, align, USE, wait);
- circle-strafing combat, backpedalling when hurt, weapon choice;
- labels for exit visibility/bearing/distance, key colours, door ahead, damage
  over the next 8 decisions.

Three teacher bugs were fixed during Phase 3 and matter for label quality:

1. **Door side-tracks were passable.** `NavGrid` treated every line touching a
   door sector as open, including the solid track walls, carving false A* paths
   through walls. Only faces between a door and a real neighbouring sector are
   passable now.
2. **Key search required a path to the far side of the locked door.** The door
   centre often lies beyond the door; the teacher never considered the key.
   Key reachability is now checked directly.
3. **Frontier fallback rescanned 40 A* goals every replan**, hanging on tier-4
   maps. It reuses one fallback goal for 240 steps and scans at most 8.

These fixes turned key/backtrack demonstrations from 0% teacher success into
100% on the purpose-built drills.

## 6. Data collection

| Dataset | Episodes | Teacher success | Purpose |
|---|---:|---:|---|
| nav (door-free, no monsters) | 250 | 244 exits | corridor/room navigation |
| arenas | 120 | 72 exits | combat, cover, ammo |
| doors (1/2 doors, key) | 400 | 395 exits | USE, door approach |
| tier-2 rooms | 80 | 28 exits | exploration |
| key drill (2 doors + key) | 150 | 150 exits | C5 skill |
| key chain (2 keys/2 locks) | 150 | 150 exits | C6 skill |
| backtrack (key behind spawn) | 150 | 150 exits | C8 skill |
| C3 suite teacher demos | 150 | 150 exits | corridor-door specialist |
| C4 suite teacher demos | 150 | 143 exits | room-door data |
| C7 suite teacher demos | 120 | 54 exits | exploration (not used in shipped expert) |
| suite DAgger | 191 | student 25 exits | failure-state labels |

Episodes store rays, entities, vitals, RGB, prev action, map crop, pose, keys,
exit labels, damage targets, action heads and the teacher's goal vector. All
data is float16/uint8 where safe; manifests record `spec_hash` and split.

## 7. Behaviour cloning

- 128-step windows with stride 64; six-head cross-entropy with head weights;
  auxiliary losses for exit visibility/bearing/distance, key colours, keys,
  door-ahead, enemy-visible and damage.
- Value head trained to the episode return; goal head trained only where a
  teacher goal exists (MSE + type CE).
- Training on PyTorch MPS, 10 CPU threads for loading and environments.
- The BC v5 checkpoint (Atlas-G) reaches train CE 0.69 and solves C0/C5/C6/C8;
  it is the navigation expert in the shipped hybrid.

**DAgger dead end.** 191 suite episodes with β=0 produced a 73% turn-label rate
because the student froze early and the teacher labelled turning for the rest of
the episode. BC v3 collapsed to 99.8% spin and 0% exits. The data was removed;
DAgger needs teacher mixing, stuck-tail downsampling or a trust region.

## 8. PPO

- Recurrent PPO with GAE, clipped surrogate, 8 parallel vizdoom environments,
  128-step rollouts, episode cap 512 decisions for map diversity, learning rate
  8e-5, goal head frozen to preserve the BC objective.
- Suite sampling: `--suite` draws 60% of maps from the train split with a
  30/50/20 mastered/current/hardest mix; the rest come from generated tiers and
  Freedoom train.
- Dense training-only potential shaping toward the nearest uncollected key
  (0.002/unit) uses privileged key positions; the shipped actor never sees them.
- PPO v2 raised mean return 1.4 → 8.5 in 40 updates but **forgot C5** (0/5) and
  did not beat BC v5 on C6/C8, so it is not the navigation expert. The run is
  documented as a negative result; PPO-25 remains the combat expert.

## 9. Architecture and routing

The shipped system has four parts:

1. **Atlas-G v1** (1.87 M parameters): ray/entity/vitals/RGB/prev/map/pose
   encoders → 672-dim concat with goal encoding → GRU(384) → factorised heads +
   value + auxiliary heads.
2. **Frozen PPO-25** (1.81 M, v1): the Phase-2 arena specialist.
3. **Door specialist** (1.87 M, Atlas-G architecture): BC on 300 C3/C4 suite
   teacher demos, anchored to BC v5. It solves C3 5/5 but forgets C5/C6, so it is
   only used behind a gate.
4. **Perception router + reflex**: enemies visible ⇒ PPO-25 for ≥16 decisions.
   Otherwise, if no locked door/key is known and a door is visible and the first
   side-ray median is <0.23 (narrow corridor), latch to the door specialist for
   the episode; otherwise Atlas-G. An observation-only reflex turns after 8
   blocked-forward decisions and presses forward+USE after 8 pure no-ops,
   disabled in combat. The policy's own action, not the override, is fed back as
   `prev_action`; the deterministic map integrates the executed action.

Details and the parameter table are in [`ARCHITECTURE.md`](ARCHITECTURE.md).

## 10. Diagnostic suite

14 categories, each isolating a capability: sanity navigation, duel, arena,
corridor door, room door, one-key lock, two-key chain, exploration, backtrack,
ambush, scarce ammo, gauntlet, Freedoom transfer and OOD. Splits, metrics,
probes and commands are in [`../training/suite/README.md`](../training/suite/README.md).

- **Fast gate**: 5 maps/category × 1 seed = 70 episodes.
- **Full gate**: 30 maps/category × 5 seeds = 2,000 episodes.
- **Headline**: tier-weighted proxy (1.0/1.2/1.5/2.0) with a stratified
  bootstrap CI over maps.
- **Per category**: exit, success@k, proxy, coverage, keys, locks, kills,
  deaths, SPL, spin, no-ops, steps. Nothing is dropped.
- **Promotion**: `training/suite/compare.py` uses a paired bootstrap. Promote iff
  the delta CI excludes zero and no category has a statistically significant
  >10-point regression. Absolute floors are applied; where the baseline also
  misses a floor, matching/beating the baseline is enough.
- **Probes**: door-angle sweep, exit-sign ablation, door-colour swap,
  observation corruption, determinism, memory wipe at key pickup.

Test/OOD runs require `--allow-test`; every look is appended to
`test_touch.log`. The final test look is `test_hybrid_ship` (+5.790).

## 11. Measurement protocol

- Maps and engine seeds fixed per split; no test map is ever trained on.
- One engine seed per map in the fast gate; five in the full gate.
- CIs are computed over maps, not episodes, so repeated engine seeds do not
  inflate significance.
- Paired comparisons use the same map IDs for baseline and candidate.
- Determinism probe: same checkpoint + seed ⇒ identical action hash, exit and
  step count (verified on C5).
- Every reported number is reproducible with a command in the README.

## 12. Compute choices (measured, not assumed)

| Workload | MLX GPU | PyTorch CPU (10 threads) | PyTorch MPS |
|---|---:|---:|---:|
| 2 M-param MLP 256×512 fwd+bwd | **4.2 ms** | 11.2 ms | 11.3 ms |
| DoomNet 16×128 fwd+bwd | — | 3.50 s | **0.22 s** |

MLX wins the stateless MLP microbenchmark but loses 16× on the recurrent policy
that is actually trained. Training therefore uses MPS; environments, collection
and suite workers use all 10 CPU threads. The submission is CPU-only (the scorer
may not have a GPU), with p50 1.7 ms / p99 2.1 ms.

## 13. Reproducibility

- `python -m training.suite.generate` builds every split deterministically;
  manifests store `spec_hash`, `generator_version`, seed, category and ticks.
- `python -m training.suite.leakage` verifies train/test hash disjointness.
- Data collection, BC, PPO and DAgger have CLI entry points listed in the README;
  checkpoints record config and update number.
- Weights are Git LFS; the evaluated commit is self-contained.
- The validator is run after every promotion; final result: PASS, 17.5 MB
  tracked, init 0.4 s, 195-step dry-run with exit, p99 2.1 ms.

## 14. Limitations and next phase

- C3 is closed by the gated corridor specialist (100% val and test). The gate is
  deliberately conservative; C4 (room-wall doors) is 0% val / 60% test because
  the specialist does not generalise to rooms and the generalist remains weak.
- C7 exploration and C9–C13 (ambush, scarce ammo, gauntlet, Freedoom, OOD) are
  still 0% exits. The teacher itself fails these maps 0/3, so the bottleneck is
  label quality and combat/exploration policy, not the suite.
- Attempts that failed are recorded in `RESULTS.md`: ungated BC fine-tunes,
  visible-door controllers, longer blind reflexes, logit blending and a pure
  frontier controller.
- The learned router is a perception rule, not a learned gate; it is intentionally
  simple and auditable.
- The full 30-map × 5-seed test has not been run; the fast test is 70 episodes.
- Proxy weights are assumptions. The official scorer is hidden.

## 15. Phase 5 changes

- **Odometry**: corrected turn-run and friction/wall-clip integration
  (`ARCHITECTURE.md` §6.1); old checkpoints run with the legacy integration.
- **Ego map**: heading-up two-scale 16×32×32 crop; demo maps regenerated
  offline by replaying stored observations (`training/egomaps.py`, bit-packed
  to 2 KB/step).
- **PPO** (`training/ppo2.py`): 9 worker processes × 6 envs, double-buffered
  inference on MPS; GAE(0.995, 0.95) bootstrapped from the next observation;
  asymmetric critic with 16 privileged features (time left, geodesic distance
  and bearing to the current objective, keys, coverage, ...); detached critic
  features so only the policy loss and anchor shape the trunk; exact KL anchor
  computed from stored anchor hidden states; 5–15 critic-only warm-up updates.
- **Reward** (training only): exit +10 (+2 × time left), key +3, lock +3,
  door +0.5, new sector +0.3, new 64-unit cell +0.01, kill +0.6, damage
  −0.01/HP, early death −(3(1−t/T)+1), time −0.001, geodesic progress
  +0.003/unit toward the current objective (exit if reachable with held keys,
  else the nearest needed key), idle penalty after 8 no-ops (`ppo_ego2`).
- **Selection**: candidates are scored on the full val split (136 episodes);
  promotion uses the paired gate; the 70-episode fast split is only for quick
  reads (its 5-map categories swing by 20–40 points).
